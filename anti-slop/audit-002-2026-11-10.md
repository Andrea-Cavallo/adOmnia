# OSGi Control Center visual review

Scope: the Control Center shell and its Bundles, Dependency graph, Activators, Diagnostics, Runtime, Applications, dependency lookup and Target platform views, including extension and p2 content.

Direction: the user's Nothing Phone request. Dot-matrix typography marks the title and real bundle filter counts; the application palette supplies neutral surfaces, semantic states and the inverted navigation selection. Standard text carries operational details.

No outstanding actionable findings in the implemented scope.

- Navigation uses named destinations and a current-page state. Each destination has a title and a short description (R-24, C-3).
- Bundle list and detail panes have independent headings. Counts remain filters rather than decorative dashboard metrics (R-17, C-2).
- Text previously rendered at 9.5–11.5px now uses 11–12px; content sections have more spacing. Monospace remains reserved for technical identifiers (R-03, C-4).
- The existing shared modal provides focus containment and Escape handling. Search, clear, selection, issue filters and all eight navigation destinations were exercised in Chromium (R-26, R-34).
- Dark and simulated light palettes, plus 1440×1000, 850×760 and 540×740 layouts were inspected. Narrow layouts stack the list and inspector; mobile navigation scrolls horizontally (R-03, C-4).
- Empty workspace, missing target and backend failure states were exercised. Run stays disabled without a target; a failed load provides a retry action (R-27).
- Browser fixtures use explicitly synthetic sample data; no sample values are introduced into the product. Browser execution reported no page errors.

Verification limit: the fixture substitutes backend reports. Live Equinox actions, native Wails interaction, imports, p2 downloads, builds and debugger connections require desktop acceptance; this visual change does not establish their end-to-end operation.
