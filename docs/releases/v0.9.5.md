# adOmnia 0.9.5 — Log Inspector reliability pass

This release makes Log Inspector more trustworthy for real developer debugging
sessions. It still keeps the local-first import flow, but the analysis now
handles recovered retries, trace-only chains, source provenance and nested
request/response bodies more accurately.

## What changed for debugging

- Request analysis now groups by correlation ID, trace ID or request ID, so logs
  that only carry a trace ID still appear in the request summary.
- A timeout followed by retry and a final 2xx response is shown as a successful
  request with retry evidence, while timeout plus missing/5xx final response
  remains a timeout.
- Durations distinguish explicit request duration from an observed log window.
  Estimated windows are marked with `~` in the overview.
- Request/response payload detection now includes `attributes.http.request.body`,
  `attributes.http.response.body`, direct `attributes.request/response` objects
  and JSON strings that need unwrapping in the detail view.
- Multi-file imports keep a stable `sourceId`, readable `sourceName`, and
  distinguish homonymous files such as `app.log #1` and `app.log #2`.
- JSON/JSONL export includes `sourceId` and `sourceName`, so evidence bundles
  retain file provenance after filtering.
- The source filter accepts both `source:` and `sourceName:` from UI actions.
- The request/response tab now falls back cleanly when the selected event has no
  payload, instead of leaving the user on an empty disabled view.
- The multi-source parser avoids spreading large arrays into `events.push`, and
  file picker loading is sequential so cancellation has a chance between files.
- Diagnostic messages avoid claiming a 10s configured deadline when the log only
  proves that observed latency exceeded 10s.

## What moved

| New file | Responsibility |
|---|---|
| `useLogImport.ts` | Getting a log into memory: sources, the background parse, progress and cancellation, the discovered field schema, and the error that came out of it. |
| `LogInspectorToolbar.tsx` | The toolbar and its three popovers (columns and noisy fields, sensitive fields, export). |
| `StatusBars.tsx` | Import progress, the error banner and the summary bar. |
| `toolbarControls.tsx` | Shared toolbar primitives — button, toggle, popover, field chip, add-field form. |
| `prefs.ts` | Persisted panel preferences and the `usePrefs` hook. |

`LogInspectorPanel.tsx` goes from **866 to 383 lines** and is now a composition
layer: it owns the derived data (mask → sort → filter), the keyboard shortcuts
and the layout, and delegates the rest. No file in the feature is above 460
lines.

Two small accessibility additions came along with the extraction: the progress
bar reports `role="progressbar"` with its current value, and the search input,
the retention selector and the add-field inputs carry explicit labels.

## Why it matters

The visible result is a Log Inspector that behaves better during demos with
multiple microservice files: a developer can filter by source, follow trace-only
chains, trust the final request outcome, and inspect request/response payloads
inside `attributes`. The internal split keeps future analyzer work localized.

## Verification

- 119 dedicated Log Inspector tests, 402 frontend tests across 77 files.
- `npx tsc --noEmit`.
- Focused regression cases for trace-only analysis, recovered retry, nested
  `attributes.http.*` payloads, source export and homonymous file names.
