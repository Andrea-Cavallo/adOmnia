# adOmnia v1.0.28

gRPC and WebSocket now work like REST requests, one screen holds API, code and data, and Java gets the External Libraries Go already had.

## gRPC

- **A module with the API workspace's layout.** gRPC calls are collection items with their own collections and tabs. The bar takes the address (`host:port`, `grpc://`, `grpcs://`), the service and method from a picker, and Invoke or Stream. The sections are Message, Metadata, Auth, Schema, TLS, Settings, Mock and Load test. Unary replies use the standard Response panel; streams arrive live in a Stream panel, and client and bidi streams stay open to send more messages.
- **No server reflection needed.** Describe a call with `.proto` files on disk and their import paths, or with a protoset. Many production servers turn reflection off: calls, streams, load tests and the mock now work without it. Paths are saved, so edits to the `.proto` apply.
- **A mock built from the `.proto`.** Rules per method answer with JSON that can use the request (`{{request.id}}`), a status code and a delay; server streams reply with an array, bidi answers every message. Reflection is on, so any client discovers it. *Use as address* points the call at it.
- **One connection per server**, reused across calls instead of a new handshake each time.
- **From the call to the code.** A call shows *Served by SayHello()* and opens the method: Go (the type passed to `RegisterXServer`) or Rust (the `async fn` of the tonic impl). In Code Studio, the `.proto` lens shows the same handler and *Call in gRPC client* opens the call with the file, its import root and the rpc selected.
- **In Flows and scripts.** A saved gRPC call is a Flow step: status, assertions and variables from the reply, like an HTTP request. gRPC codes map to HTTP-like statuses (NOT_FOUND is 404).
- The old gRPC panel is gone. Its saved connections become calls the first time the module opens, and a dropped `.proto` opens a call.

## WebSocket

- **A module with the REST layout.** Connections are collection items with their own collections and tabs: the bar with `WS`/`WSS` and Connect/Disconnect, saved messages, Params, Headers, Auth, Settings, Script, Mock and Parallel, and a Messages panel with filters, search, pause, export and an inspector. The old panel's connection and templates move into a tab the first time you open WebSocket.

## API, code and data on one screen

- **Smart Split Workspace.** Code and request side by side, plus a third pane for Database Studio, Broker Studio or Logs when a breakpoint, a query or a topic needs it. *Back to response* (Alt+←) returns to the previous screen. The header names what you are working on: project, service, route, handler, request and run.
- **API ↔ code link.** A request opens its handler; an endpoint browser lists the endpoints of the open projects; Go and Spring request bodies are filled from the code.
- **One-Click Debug Scenario.** Save a Debug Request with its environment, test data, breakpoints and check queries. Run it again in one click and see what changed since the previous run.

## Code Studio

- **External Libraries beyond Go.** Maven, Gradle, Python and native projects list the libraries the build resolves, transitive ones included, with sources to browse read-only. For Maven the sources come from the `-sources.jar`; *Download sources* shows the exact Maven command first. In a `pom.xml`, *View source* and Ctrl+click on a `<dependency>` open the library's code.
- **Java RCP/PDE.** With a target platform chosen, JDT LS works on PDE workspaces through a shadow workspace: completion, live errors, cross-bundle navigation and debugging on the real files. Eclipse applications (`.product`, `.launch`) run and debug from the OSGi Control Center. Also new: `plugin.xml` extensions with diagnostics, a Dependency Explorer, uses-constraint conflicts, export and p2.
- **Active directory pin** above the Project tree, and **indent rainbow** in Python and YAML.

## MCP

- **Project build.** `project_build_plan` and `project_build` plan and run builds through the language adapters, project wrappers first, without downloading anything.

## Known limits

- gRPC: Java and Python services are not detected in code yet, so they have no *Served by* link; *Debug* on an rpc is Go only; streams are not recorded in history or Flows; the schema-driven form of the old panel is replaced by the JSON editor with *Example* and the field list.
- External Libraries reads the local repositories and caches; libraries the build has not downloaded yet show as such.
- Verified by automated checks, including gRPC calls against real servers without reflection and the mock built from `.proto` files. Native visual acceptance of the new modules in the desktop app on Windows, macOS and Linux is still manual.
