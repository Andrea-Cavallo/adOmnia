# v0.9.41 — Go Studio: a concurrency-first debugger

Go programs are concurrent, so their debugger should start from goroutines.
The Debug tool window is rebuilt on top of Delve: every pause shows what
each goroutine is doing, what it waits on, and where the program is stuck.

## Session: goroutines first

- **Goroutines grouped by origin.** Package → function started by the `go`
  statement → goroutines, with the current goroutine first.
- **States that explain the wait.** Running, chan receive, chan send,
  select, mutex, WaitGroup, cond, sleep, I/O wait and syscall. Go Studio
  reads them from each goroutine's stack, because DAP does not expose Go's
  wait reason.
- **Blocked on.** The expression the goroutine waits on, read from the
  source line: `order := <-s.orderChannel` shows *Blocked on
  s.orderChannel*.
- **Goroutine detail.** State, blocked on, *Started in*, location and the
  source line, each one click away from the editor.
- **Call stack** with runtime and library frames folded, **variables** with
  package globals, typed colours, copy value and lazily loaded scopes, and
  the **console** with the Delve REPL.
- **Inline values.** While paused, the values of the current function's
  variables appear at the end of its lines, as in GoLand.

## Concurrency view

- **Diagnostics**, most severe first:
  - *Possible deadlock*: every goroutine waits on another one.
  - *Channel blocked*: goroutines waiting to send or receive on the same
    channel at the same line.
  - *Mutex contention*: two or more goroutines waiting for the same lock.
  - *Possible goroutine leak*: 10 or more goroutines from the same function
    stuck at the same line.
  - *Data race*: a report from the race detector.
- **Goroutine flow.** For every starting function: its goroutines,
  coloured by state, and the channels, mutexes and WaitGroups they wait on.
  A resource shared by several functions is highlighted.
- A **Refresh** button takes a new snapshot without resuming.

## Race detector

- *Run → Test Current Package with Race Detector* runs `go test -race`.
- Race reports from tests, runs (add `-race` to a run configuration) and
  the debug console become cards: both conflicting accesses with their
  stacks, and the stack that created each goroutine. Every frame opens the
  source.

## Keys and look

- F6 (Eclipse) and F10 (VS Code) also step over, and F5 also resumes, only
  while the debugger is paused. F8, F7, Shift+F8 and F9 are unchanged.
- The toolbar groups Rerun/Resume/Stop and the step actions, with a clear
  Paused/Running badge and a Session / Concurrency switch. Text is larger
  throughout.
- Two styling bugs are fixed: the `danger` colour was missing, and coloured
  icon buttons lost their colour under Tailwind 4.

## Verified

- Go Studio Go tests pass, including goroutine state inference, blocked-on
  parsing and race report collection from `go test -json`.
- 768 frontend tests across 170 files, TypeScript, the production build and
  the startup budget pass.
- The new panels were checked against a simulated paused session. A real
  Delve session with blocked goroutines still needs a manual check.

## Limits

- States are inferred from stacks; a goroutine parked in an unknown runtime
  function shows as *Waiting*.
- The analysis covers the first 1000 goroutines of a pause.
