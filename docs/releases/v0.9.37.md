# v0.9.37 — Go Studio: terminal, tests, debugger and GoLand parity

Go Studio now covers the whole write → understand → run → test → debug loop.
This release adds a real terminal, a structured test runner with coverage, a
Delve debugger, GoLand-style refactoring and navigation, Git in the editor,
links to the rest of adOmnia and separate project windows. Everything stays
local, and nothing runs until you trust the project.

## Sessions, terminal and restore

- Several projects stay open side by side and stay isolated: output,
  diagnostics, run configurations and terminals never mix.
- Tabs, layout and unsaved buffers are restored after a restart. Recovered
  buffers are offered, never applied silently.
- Run configurations are saved per project, and secret values are never
  written to disk.
- A real PTY terminal (ConPTY on Windows) opens in the tool window. Closing it
  stops its whole process tree.
- A file watcher reloads clean buffers and warns about modified ones when
  files change on disk. The same file open in two projects is detected
  before anything is overwritten.

## Tests, coverage and debugger

- The test runner shows results as a tree (`go test -json`). Failures link to
  file and line, and Rerun Failed runs only what failed.
- Coverage is shown in the editor and cleared when the source no longer
  matches.
- The Delve debugger (DAP) supports breakpoints, stepping, stack, variables
  and watches, from the gutter ▶ or the Run menu. It can also attach to a
  running process or connect to a remote `dlv --headless`. Stop leaves no
  `dlv` or debuggee processes behind.

## GoLand parity

- Refactoring through gopls code actions (Extract Variable/Constant/Function,
  Inline, Move to New File), with a multi-file preview. Changes apply to all
  files or to none.
- Navigation: implementation and super-method gutter markers, back/forward
  history, bookmarks (F11), Search Everywhere (double Shift), structure view
  synced with the caret.
- Go Tools menu: `go vet`, `go generate`, `go fix`, `go mod why`,
  `go mod graph` and `go doc`, each with a preview of the exact command.
- Editor: local history per file, a TODO window, split editor with its own
  tabs, GoLand keymap, and support for Plan9 assembly, `go.sum` and
  `.golangci.yml`.

## Git, adOmnia integration and windows

- Git in the editor: branch and changes in the toolbar, gutter diff with
  per-hunk revert, blame, file history, commit and branch switch. Push, pull,
  merge and rebase stay in Git Studio.
- Git Studio follows the project open in Go Studio: it points at the
  project's repository, including when the project is a subfolder of it. A
  repository picked by hand in Git Studio is kept until you switch project.
- Project Services opens Docker Lab, Database Studio and Broker Studio with
  the services detected from `go.mod`. HTTP route handlers get an "Open in API
  Client" CodeLens. Plugins receive read-only Go Studio events (contract v1).
- Go Studio workspaces are separate from adOmnia API workspaces.
- A project can move into its own window (File → Open Project in New
  Window). Only one window at a time can edit a project, closing a window
  asks about unsaved files, and the project returns to the main window.
  Separate windows are new in this release: they are covered by automated
  tests, while the manual check in a real window is still open (M31 in
  `todo-ide.md`).
- The Go Studio chrome is redesigned in JetBrains style: tool stripes, a
  vertical Run toolbar and larger, more readable panes.

## Reliability

- Process output is never lost at exit and never splits a UTF-8 character.
  The run limit holds under concurrency.
- Saves are ordered, a corrupt state file no longer blocks Go Studio, and
  recovery buffers are case-sensitive on Linux.
- Fixed a data race when starting the debugger.
- Go Studio is kept out of the startup bundle, so the initial JavaScript
  stays under the 650 kB budget.
- `build.ps1` no longer aborts when its output is redirected (CI,
  `Tee-Object`), and it warns if the Wails CLI differs from the `go.mod`
  version.

## Verified

- 711 frontend tests across 159 files, TypeScript, the production build and
  the startup budget pass.
- `go vet`, staticcheck and `go test -race` pass for `internal/goide`
  (including `dap` and `lsp`) and `internal/goidewindow`, on Windows, with
  Delve installed.
- `build.ps1` was checked through the Wails 3 pipeline, with redirected
  output and in `-GoOnly` mode. `-Version` is embedded in the Windows
  executable.
