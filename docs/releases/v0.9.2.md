# adOmnia 0.9.2 — Faster log search and nested JSON

This release sharpens the Log Inspector for the job it exists to do: finding one
thing in a wall of pod output, fast, without leaving the machine.

## Find any field, not just the modelled ones

Search used to know twelve fields. It now resolves **any key in the event
payload**, so the value you actually have in hand is the value you can type:

```text
merchantId:M-4471          any key in the payload
http.status:502            nested key
requestId:idem-77          modelled field
```

The payload index is built lazily per event and cached, so queries that never
mention an unmodelled field cost nothing.

## Regular expressions and alternatives

```text
/timed ?out/               regex as a bare term
pod:/^pay-\d$/             regex as a field value
level:warn|error           alternatives
```

Regular expressions are always case-insensitive, may contain spaces, and degrade
to a literal search when malformed instead of throwing. A pasted URL such as
`https://host/path` still behaves as a full-text term.

## Field aliases that match how loggers actually write

Aliases are now matched canonically — case, `-` and `_` are ignored — so one
entry covers every spelling: `correlationId`, `correlation_id`, `correlation-id`,
`CorrelationID` and `CORRELATION_ID` all resolve to the same field.

The alias set was widened to cover the common emitters out of the box: ECS
(`log.level`, `service.name`, `trace.id`), OpenTelemetry (`severityText`,
`otel.trace_id`), Serilog CLEF (`@t`, `@l`, `@m`), Python `logging` (`asctime`,
`levelname`, `module`), log4j2 (`timeMillis`), Monolog (`channel`), GELF
(`shortMessage`), Datadog (`dd.trace_id`), Spring MDC (`mdc.correlationId`),
OpenShift (`project`, `nodeName`) and gateway headers — `X-Correlation-Id`,
`X-Request-Id`, `X-B3-TraceId`, `X-Amzn-Trace-Id` and `X-Idempotency-Key`.

## Nested JSON, unwrapped

Logs bury JSON inside JSON strings. Decoding is now **recursive** and covers more
carriers (`result`, `error`, `exception`, `detail`, `context`, `params`,
`attributes` alongside `message`, `body`, `payload`, `response`, `request`,
`data`), so a gateway that logs a body which itself contains a serialized payload
comes back fully unwrapped.

The JSON tab gained an **Unwrap** toggle, on by default, that turns every
escaped-JSON string in the event into a real subtree — expandable, searchable,
copyable, and pretty-printed in the raw view.

## Empty state rebuilt

The Log Inspector opening screen is now full width instead of a narrow centred
column: header with a discreet `local only` marker, drop zone and editor side by
side at equal height, the five samples on a single row, and the shortcuts on one
bar along the bottom. The duplicate clipboard button and the disabled `oc logs`
placeholder are gone; the `ctrl v` hint moved next to **Analyze**.
