# adOmnia 0.9.4 — Multi-file Log Inspector

Log Inspector can now reconstruct one request across the separate log files
produced by several microservices. It also exposes the request and response
payloads that structured Go loggers commonly place under `attributes`.

## One investigation across several files

**Open** supports multi-selection and drag-and-drop accepts several files at
once. Every file is parsed independently, which preserves its JSON, JSONL or
mixed-log boundaries, then the normalized events are combined into one
chronological dataset. A four-service investigation can therefore load four
files and filter the complete chain with `correlationId:<value>`.

Each event retains its source filename. Combined imports show a **Source file**
column and `source:wallet.log` filters the dataset to one producer. Correlation,
request analysis, histograms, export and existing field queries operate on the
combined event set.

## Request and response bodies are visible

Promoting fields such as `attributes.operation` previously consumed the whole
`attributes` object. Sibling values could then disappear from the normalized
payload. Normalization now removes only the exact promoted leaf while retaining
the rest of the object.

The event detail panel adds **Request / Response**. It recognizes structured
request and response bodies under common `attributes` and HTTP paths, unwraps
escaped nested JSON and renders each available body as an expandable JSON tree.
The original JSON remains available in the JSON tab.

## Columns follow the data

The event list and its column chooser now inspect the loaded dataset. Pod /
Container, Logger, Thread and every other optional column are omitted when no
event provides a value, instead of reserving blank space and filling rows with
dashes. Source file appears automatically only for combined imports.
