# adOmnia v0.9.70 — Live Collaboration and a new identity

adOmnia gets a new icon, a quieter interface and its first collaboration
feature: share collections, requests and environments with colleagues on the
same network, without a cloud account and without leaking secrets.

## Live Collaboration (LAN)

Workspace › Live Collaboration lets one adOmnia host a session that colleagues
join with an invite code.

- **Private by design:** traffic is encrypted with TLS 1.3. The guest checks the
  host's certificate against the fingerprint carried by the invite, so no
  certificate authority and no internet connection are involved.
- **Controlled access:** invites work once and expire. Participants are Viewer,
  Editor or Controller; the host enforces roles and can change them or remove
  someone at any time. Repeated wrong codes are slowed down, and browser pages
  on the network cannot connect.
- **What you can share:** a collection, an open request, or the environments not
  marked private.
- **Secrets stay home:** tokens, passwords, API keys and vault references are
  removed by the backend before anything leaves the machine, and removed again by
  the host on content a guest sends. A preview shows exactly what will be sent
  and which values were removed.
- **Nothing is imported silently:** received items wait in an inbox. They are
  imported only when you accept them, with new IDs so they never overwrite your
  data. Removed secrets come back empty, and items containing pre/post scripts
  are flagged because those scripts would run on your machine.

Sessions currently use an explicit address and port. Live co-editing, network
discovery and reconnection are planned next.

## New icon and theme-aware branding

- A new hexagonal adOmnia mark replaces the previous logo. The neon tile is the
  executable and launcher icon on Windows, macOS and Linux.
- The in-app logo, favicon and the running window's icon follow the theme:
  white mark on Dark, black mark on White. Windows updates the window and
  taskbar icons, macOS the Dock icon, Linux the GTK window icon. Win95 and
  Sketch keep their own artwork.
- Executables and pinned shortcuts keep the neon icon. `icon-white.ico` and
  `icon-black.ico` are provided for customizing Windows shortcuts, and Linux
  packages install a symbolic icon that desktops can recolor.
- Windows may show a cached old icon for an existing shortcut until it is
  recreated. Details are in `docs/BRANDING.md`.

## A quieter interface

- The Hub drops its top bar; Ctrl/Cmd+F opens the command palette from the Hub.
- Global search now sits at the bottom of the rail, next to Settings, with a
  search icon. The rail shows the theme-aware app icon.
- The request and response panes no longer repeat "Request" and "Response"
  titles; the status line starts directly with the result.
- JSON highlighting uses a calmer, neutral palette in Dark and White, with
  brackets that follow theme tokens instead of fixed bright colors.

## Under the hood

- The Go root is a thin Wails binding layer again. Logic moved into
  `internal/`: update check, dropped-file import, window chrome, log files, AI
  gateway helpers, MCP sessions, Live Development Session tools, Go Studio
  storage and the AI context filter. Binding names are unchanged.
- The README has a new banner and current screenshots.
- Internal working notes moved to `mds/`; the root keeps README, LICENSE,
  CHANGELOG and the GitHub community files.
- Linux builds regenerate the embedded GTK icon resource, and the macOS build
  regenerates the icon set when the artwork changes.

## Validation

All 270 frontend test files and 1,212 tests pass, as do TypeScript, the

and the Go suites for the moved packages and the new collaboration engine pass
