# v1.0.20 — Rust editing features, live Python runs, build units, persistent collaboration

Rust gains semantic tokens, inlay hints, Code Vision and cargo
aliases; a Python run becomes a live session; Code Studio shows build units everywhere and groups
Problems by them; Procfile, Make and compose entries join the Detected flow; collaboration
recovery survives a restart and a crash; and six panels get a sharper, denser layout. No project
data format changes and no migration is needed.

## Code Studio

- **Rust editing is complete.** Semantic tokens, inlay hints and Code Vision (callers/callees)
  are on for rust-analyzer. The providers are generic LSP and start only for the capabilities the
  server announces, so a project without rust-analyzer behaves as before.
- **Rust tells you what to do.** A build that cannot find the MSVC linker explains the remedy in
  the console (Visual Studio Build Tools with the C++ workload, reopen the app for the new PATH, or
  a `*-pc-windows-gnu` toolchain), once per run, covering both the `linker link.exe not found`
  message and `LNK1181` without the Windows SDK.
- **Toolchain without surprises.** `RUSTUP_TOOLCHAIN` is a real candidate in *Select Rust
  Toolchain*; a channel declared by `rust-toolchain.toml` and not installed shows the exact
  `rustup toolchain install …` command; runs, tests, the debug build and the `rustc` probe set
  `RUSTUP_AUTO_INSTALL=0`, so rustup never downloads a toolchain by itself. `cargo test` uses the
  same channel as the run.
- **Rust environment and analyzer cache.** *Rust → Rust Environment…* lists `CARGO_HOME`,
  `RUSTUP_HOME`, `CARGO_TARGET_DIR`, `RUSTFLAGS`, `[alias]`, `[env]` and `[target.*]` read from the
  filesystem, plus the rust-analyzer target folder and its size. *Clean analyzer cache* stops the
  analyzer and deletes only that folder: never your `target/`, never a folder chosen with
  `CARGO_TARGET_DIR`.
- **Build units are visible.** The project tree labels the folders that are build units with their
  language, workspace symbol search shows the language of every result (SDK files included), and
  Problems is grouped by unit with a badge, a count and a filter on file, unit, message, source or
  severity. The AI fix actions follow what is visible; the Markdown export still exports
  everything.
- **cargo aliases are Run entries.** `cargo dev`, `cargo lint` and the rest of `[alias]` are
  proposed in Run, alphabetically and bounded, from the project and the unit `.cargo/config.toml`.

## Languages and Run

- **Python runs are live sessions.** A `script`/`module` run (`python -m uvicorn app:app`,
  `python manage.py runserver`) now becomes a Live Session with its port, local URL and traffic,
  like Go and Rust. Previously no Python run ever reached the Live Session panel.
- **Detected entries beyond language adapters.** The Run bar proposes the processes of a
  `Procfile` (`web`, `worker`, …), one entry per `Makefile` rule and one per compose service, only
  when `make`/`docker` are installed. A Procfile line stays shell-free when it fits, and falls
  back to `sh -c`/`cmd /c` when it needs `$PORT`, a pipe or `&&`. No new runner is involved.

## Collaboration

- **Recovery survives a restart and a crash.** An encrypted snapshot in the local bbolt store
  holds the session (host certificate and address, participants, roles, resume tickets), the replay
  window, the shared documents, the received-shares inbox and the guest Yjs baseline. `Restore`
  runs at startup without opening a listener, a recovered host reopens with *Resume* on the same
  address and certificate, a guest resumes its identity and its unsent text, and expired, revoked,
  corrupt or out-of-window recovery is reported instead of silently lost.
- **Typing does not rewrite the document history.** Document checkpoints are coalesced (one write
  per window, flushed on close and on shutdown), so the stored Yjs history is not re-encrypted and
  re-written on every keystroke.

## Appearance

- **A sharper, denser layout for six panels.** Mock, Proxy, Settings, SOAP, SSE and Vault share a
  Nothing-inspired language: 3px corners, transparent groups with hairlines, smaller type for dense
  controls, a sidebar that reads like a list of tools, and container queries so the layout reflows
  in a narrow split or a detached window. Behaviour is unchanged.
- **A demo animation in the README**, so the first thing on the project page is the product.

## Removed

- **The MCP Server Generator panel.** The panel, its rail entry, the feature-registry and AI
  capability entries, and the legacy Wails v2 binding are gone. The local server is unchanged:
  `adomnia mcp` still exposes collections as MCP tools from the CLI.
