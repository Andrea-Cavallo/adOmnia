# v0.9.48 — Go Studio Project control and a cleaner gO rail

This release makes the Project view behave more like an IDE and makes the gO
entry in adOmnia's compact navigation feel like a deliberate product mark,
not an oversized button.

## Project actions that match the file

- A `.go` file's context menu now exposes **Find Usages**, **Inspect Code**,
  **Refactor This**, **Move to New File**, **Bookmarks**, **Reformat Code**,
  **Optimize Imports**, **Run Current Configuration** and **Debug Current
  Configuration** alongside the existing file and package actions.
- Folders and non-Go files stay focused: they do not show Go-only code actions.
- Every new menu item hands off to an existing Go Studio command; it is not a
  decorative or disconnected action.

## Explicit disk refresh, without losing work

- **Reload from Disk** re-reads the selected file even when the watcher has
  not reported a change. If the editor has unsaved text, Go Studio asks before
  replacing it.
- **Refresh Folder** and **Refresh Project** reload the corresponding cached
  directory branch. Clean open tabs adopt their on-disk content; dirty tabs
  remain protected and use the existing Reload / Keep / Compare decision.
- A compact refresh button in the Project header exposes the project-wide
  operation and shows progress while the tree is refreshing.

## A compact gO identity

- The Go Studio rail button now uses the supplied cyan gO artwork as a small
  transparent PNG. The logo does not receive an extra tile or frame; the
  rail's restrained left-side active marker remains the selection feedback.
- The launcher still opens Go Studio directly. The same mark is also used
  wherever the rail needs the Go Studio feature icon.
- The README's Go Studio section now presents the updated
  `assets/images/go-ide.png` workspace screenshot before describing the IDE.

## Removed: Brick Workshop

The Brick Workshop / LEGO-inspired skin is no longer shipped: its theme
definition, scoped CSS, Hub art, appearance controls, translations, tests and
historical release references are removed. No workspace or settings migration
is needed; users simply continue with the remaining built-in appearances.
