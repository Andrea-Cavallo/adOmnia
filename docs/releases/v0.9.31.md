# v0.9.31 — a living Hub and a more deliberate a0

## Hub and mascot

- The Hub now places a0 at the center of the four main work cards as a complete
  full-body character. Dedicated transparent renders replace the cropped asset
  and the improvised arms that broke the silhouette at Hub scale.
- Code, Docs, Git and Settings each produce a distinct pose and expression.
  Persistent image layers cross-fade instead of swapping abruptly, while small
  position, icon and card reactions make the interaction feel connected.
- Pointer and keyboard focus drive the same reactions. Custom movement stops
  when the operating system requests reduced motion.

## a0 and Bug Hunt

- Clicking the Hub mascot opens the existing compact a0 chatbot only after
  **Test connection** has verified the currently selected AI provider and model.
- If AI is not ready, a small notice explains the requirement and **Configure
  AI** goes directly to Settings → AI Engine. No provider is contacted merely
  by clicking the mascot.
- Bug Hunt has one deliberate entrance: ask a0 to play. Phrases such as **“I
  want to play”**, **“Let's play Bug Hunt”**, **“Voglio giocare”** and
  **“Facciamo una partita”** launch it locally without an AI round-trip.
- Mentions and negative instructions such as **“Tell me about Bug Hunt”**,
  **“I don't want to play”** and **“Non aprire il gioco”** do not launch it.
- Dragging or spinning the Hub logo is now a harmless visual fidget. It never
  reveals a dialog and never starts the game.

## Workspaces and appearance

- Themes, Templates and Plugins are consolidated inside Settings and remain
  directly routable. The Workspace rail is focused on Git Sync.
- **Terminal Green** joins the built-in appearances: near-black surfaces,
  signal-green accents, complete syntax colours, scoped recolouring of adOmnia
  brand marks and WCAG AA contrast checks. It is also available in the status
  bar's quick appearance cycle.
- **Brick Workshop** has a deeper physical treatment across the app rail, tabs,
  request list, workspace header, editors and glass actions, while preserving
  visible active states and reduced-motion behavior.

## Broker Studio

- Broker navigation is centered on saved connections and their events instead
  of duplicating protocol destinations in the rail.
- Kafka and the shared Broker Studio now keep connection context close to
  browsing, producing and consuming; the connection model has dedicated
  regression coverage.

## Project material

- Added an accepted architecture direction for exposing the running adOmnia
  desktop as a local, permissioned MCP server without creating a headless
  workspace engine.
- Added an interactive three-variant design sketch for connection-refused
  responses, covering compact recovery, guided diagnostics and a hybrid card.
- Removed obsolete internal Bug Hunt, Log Inspector and refactor scratch
  documents; current behavior and release history remain in the maintained
  product documentation.

## Validation

- Frontend TypeScript production build.
- Complete frontend Vitest suite.
- Go build and complete Go test suite.
- Browser smoke check of Hub mascot reactions, unverified-AI guidance and the
  direct Settings → AI Engine route.
