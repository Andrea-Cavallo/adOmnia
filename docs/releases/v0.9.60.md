# adOmnia v0.9.60

This release closes the first two levels of the gO Studio plan: an IDE you can trust all day (P0) and a Go workflow that goes beyond the terminal (P1). Go Studio now understands your project's architecture, errors, routes, data access, documentation and `context.Context` flow from the types. It compares benchmarks with statistics and gives fuzzing its own studio. Linux follows its native Wayland or X11 session.

## Understand the project from the code

- **Architecture Explorer.** The import graph, calls between packages, a call graph around any function, the module graph, and every entry point and service (`main`, HTTP routes, gRPC, Kafka producers and consumers, repositories, jobs, CLI commands). Each one opens its code or the matching studio.
- **Interface Explorer.** Implementations and near-implementations with the methods they are missing, who uses each interface and which methods they really call.
- **Data access.** database/sql, sqlx, pgx and GORM calls with their SQL, tables, transactions and prepared statements. Any table or statement opens in Database Studio.
- **REST routes.** Handlers, middleware and request/response DTOs are understood from the code. Route lenses add *Mock*, *Copy cURL* and *OpenAPI*.
- **Documentation.** Every package as `go doc` shows it, plus `.proto` files. One-click generation of `docs/API.md`, `docs/ARCHITECTURE.md` with Mermaid diagrams, `docs/openapi.json` and `docs/PROTO.md`. *Tools → Architecture Decisions* opens the ADRs in `docs/adr`.
- **Dependency report.** The Dependency Graph exports a local JSON report.

## Go-specific analysis

- **Context propagation across packages.** The *Context graph* is now drawn. Its *Project* scope follows `context.Context` through calls between packages and lists every place that drops the caller's context for `Background()`/`TODO()`. In the debugger, a context carrying a trace or request id opens the Log Inspector on that id.
- **Error Handling Intelligence.** Ignored, discarded and shadowed errors, `%v` instead of `%w`, `==` instead of `errors.Is`, and more, grouped by rule with one-click fixes.
- **Benchmark comparisons.** Compare with the previous run, main/master, any commit or a pinned baseline, with medians and a Mann-Whitney test so you can tell a real change from noise.
- **Fuzzing Studio.** Targets, corpus, typed inputs, runs, replay, and crashes grouped with the minimized input.
- **Worker pool saturation** in the debugger's Concurrency view.

## Runtime connections

- **SQL outcome in Live Session.** Time, rows, errors, slow statements, possible N+1 patterns and open transactions per request.
- **Observability.** Spans form a parent/child tree. A trace opens a multi-service view, and spans of a live debug request open its Split Debug View.
- **WebSocket binary frames** show as Hex/ASCII.

## Everyday fixes

- **API Workspace in its own window** now shows the collections next to request and response, also when opened from Go Studio's Studios launcher.
- **Toolchain changes keep gopls in sync.** Switching, installing or resetting the Go SDK restarts gopls. SDKs are ordered by real version.
- **SonarQube setup** explains why a scan cannot start and which server URL it needs.
- **Settings save immediately**, in order, with visible errors.
- **Linux** follows the native Wayland or X11 session. Local builds use GTK4 and show the right window icon. Code editing scrolls and moves the caret smoothly, and reduced-motion settings are respected.
- **Crash recovery** is measured automatically with 10 unsaved files: snapshots stay well below the typing pause, and restore is immediate.
