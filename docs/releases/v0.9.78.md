# adOmnia v0.9.78

## Redis in Database Studio

- New **Redis** connection type: host/port/DB index, ACL username and password, TLS, or a `redis://` / `rediss://` URI. Test Connection runs an authenticated PING.
- **Key Explorer**: SCAN-based listing (up to 1,000 keys, never `KEYS`), local search, and one-click inspection of type, TTL and value.
- JSON command runner (`{"command":"GET","args":["user:1"]}`) on top of the existing query tabs, history, favorites, variables, timeout and JSON/CSV export. It supports string, hash, list, set, sorted-set and stream commands.
- Writes ask for confirmation in the UI and in the backend. Server-control commands, scripts, transactions and subscriptions are blocked.
- Credentials keep the existing session-only/Vault protection. Previous SQL/MongoDB connections load unchanged. Guide: `docs/DATABASE-REDIS.md`.

## API workspace

- **Browser-style request tabs**: rounded tabs that stay visible, a colored method badge, a close button on every tab, and a full-width accent underline on the active tab. The new-tab button is now round.
- A click no longer leaves a focus ring. The ring now appears only during keyboard navigation.
- Request bar with a **Request · name** caption, a wider method selector, and an overflow menu for API Tools, Save and Delete.
- Section strip shows Params, Headers, Body and Auth. The other sections are under **More**, and each keeps its saved state.
- **Nothing-style Send**: same colors as the skin (black skin: black button, white label; white skin: the reverse), segmented frame and dot-matrix SEND label. No invented colors.
- **Cleaner composer**: the section tabs and the body toolbar appear only when you hover or focus the request area. An empty body opens straight into a JSON editor.
- **Environments and Hosts** switchers moved into the API Workspace header, larger and easier to read. The sidebar keeps only the Workspace switcher.
- Nothing-style empty response state with a dot-matrix glyph and palette colors.

## Environments for all of adOmnia

- **One environment set for every module**: HTTP, WebSocket and SSE as before, and now also Database Studio (queries and every connection field: host, user, password, DSN…), gRPC (address, metadata, payload), Broker Studio and Kafka, SOAP (URL, headers, envelope, resolved before WS-Security signing), and Go Studio runs, which receive the active environment as process variables (`{{NAME}}` also works in run-configuration values).
- Database Studio now updates as soon as you switch environment.
- **Stages side by side**: the environment manager has a **Matrix** view (one row per variable, one column per stage) and **Add stages** creates Development, Testing, Certification and Production. Each stage is still a normal environment, so stored data, `.adomnia` workspaces and Collaboration sharing are unchanged.
- **Import / Export** of all environments in one JSON file. Private environments and plain-text secrets are left out; `vault:` references stay encrypted. Import accepts that file and Postman environments, and merges by name without deleting local variables.
- **+ Manage environments** in the Hub; the manager opens from anywhere. Right-click an environment to create, rename, duplicate or delete it; *+ New environment* sits under the list.
- Environments and Hosts switchers moved to the API Workspace header.

## Collections

- A new subfolder expands its parent folder, so creating nested folders is visible immediately.

## Hub

- The animated FOLD (WebGL) mark is replaced by a **static adOmnia wordmark** with the hexagon mark as the "o". Its glow and gradient follow the active palette, and it stays sharp on slow machines. Clicking it still opens the Arcade.
- `three` is no longer a dependency. Initial JavaScript dropped to **580,144 bytes**.

## Status bar

- Removed the error code and the "history N reqs" counter on the left, and the workspace name on the right.
- **Dark / White** switch the theme and reset accent and base colors to their defaults.
- New **Custom** button opens the accent and base color menu. It replaces the old right-click on Dark/White.

## Live Collaboration (progress)

- Shared environments with a per-variable opt-in for secrets. The Go filter always excludes private environments and Vault references.
- Collection inbox: import as new, confirmed replace, or field-by-field merge. Previews that are out of date are refused. Revisions use canonical SHA-256 hashes.
- Live editing in Go Studio with Yjs + Monaco: an opaque Go relay, host-created rooms, editor/viewer roles enforced by the server, and remote cursors and selections. Yjs loads lazily, outside startup.
- Read-only remote project for guests, confined to the host root. Private, binary and credential files are excluded. gopls never starts for guests.
- Reconnect resumes from `seq` with a bounded replay. Collection snapshots are opt-in and batched. A local audit log in devlog stores no secrets.
