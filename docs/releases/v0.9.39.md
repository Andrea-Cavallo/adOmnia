# v0.9.39 — Go Studio runs Makefiles and Dockerfiles, Developer Context and a new Hub

Go Studio now runs Makefile targets and Dockerfiles with the real `make` and
`docker`, including the container, which Stop really stops. It highlights
every file type it opens, not only Go. adOmnia also reads the project open in
Go Studio: routes, services, datasources, contracts, tables and topics become
actions in the palette and in the other studios. The Hub introduces the
aO → gO ecosystem.

## Makefiles and Dockerfiles run for real

- **▶ in the gutter of a Makefile.** Every target gets *Run 'make target'*.
  Variables, `.PHONY` and pattern rules do not. Output streams to the Run
  console, and Stop and Rerun work like `go run`.
- **▶ in the gutter of a Dockerfile.** Every named stage (`FROM … AS builder`)
  and the final `FROM` get *Build image* and *Build & Run container*. The
  build uses `docker build --progress=plain`, so the log reads well in the
  console.
- **Build & Run.** The container starts only if the build succeeds, with
  `docker run --rm -i` and the ports the Dockerfile declares with `EXPOSE`.
  *Stop* runs `docker stop` on the container: killing the Docker client alone
  would leave it running. The same happens when trust is revoked, the
  project closes or adOmnia quits. *Rerun* runs the build and the container
  again.
- **Three new Run Configuration types.**
  - *Make target*: Makefile, targets, `VAR=value` and environment.
  - *Docker build*: Dockerfile, context, tag, stage, `--no-cache` and build
    args.
  - *Docker build & run*: the same, plus ports, volumes, container command
    and container environment.

  They appear in the toolbar selector next to `go run .`.
- **Save as Run Configuration…** from the ▶ opens the prefilled form. From a
  Dockerfile it lists the `ARG`s. Names such as `password`, `token`,
  `secret` or `key` are marked secret: only the name is saved, and the value
  is asked when you start. A Dockerfile with `ARG username` /
  `ARG password` for a private registry therefore works without credentials
  on disk.
- **Secrets never reach the command line.** Secret build args and container
  variables are passed as `--build-arg NAME` / `-e NAME`, and Docker reads
  their values from the process environment. They do not appear in the Run
  console, in history or in the saved state.
- **make on Windows.** Go Studio looks for `make`, `gmake` and
  `mingw32-make` on `PATH`, then GnuWin32. A different binary can be set in
  *Go → Tool Paths*. If none is found, the message explains how to install
  one (winget, choco or scoop).
- **Docker not running?** Go Studio checks the daemon before starting and
  says to start Docker Desktop, instead of showing a raw connection error.
- **Safe by design.** Everything requires a trusted project, and arguments
  never go through a shell.
  - Make accepts targets and `VAR=value`, not flags; use `MAKEFLAGS` for
    `-j`.
  - Tags, stages and ports are validated.
  - The Dockerfile, the context and the volumes must stay inside the
    project, so the Docker socket and host folders cannot be mounted.

## Islands look

- Project, Editor, Structure and the bottom tool window become rounded
  islands on a darker ground. The gaps between them are the resize
  handles; there are no hairlines.
- Toolbar, tool stripes and status bar sit on the ground without borders.
  Editor tabs are pills, and the active tab is a raised block.
- Tree selection is softer, with an accent ring and roomier rows.
- Monaco, the terminal and the inner tool windows (Tests, Debug, TODO,
  Terminal, Problems, split editor) blend into their island.
- Everything uses theme tokens, with a light variant: grey ground and
  white islands.

## Every file is highlighted

- HTML, CSS/SCSS/Less, JavaScript/TypeScript, XML/WSDL/XSD, SQL, Protobuf,
  GraphQL, shell, PowerShell, batch, Dockerfile (including
  `Dockerfile.dev` and `*.dockerfile`), `.env` / `.env.*`, TOML/INI,
  Python, Rust, Java, HCL/Terraform and more were shown as plain text. They
  now use the languages Monaco already ships. `.tmpl` and `.gohtml`
  templates are highlighted as HTML.
- Makefiles get their own tokenizer, which Monaco does not include. It
  covers targets, variables, `$(…)` expansions, directives and comments.
  Makefiles are always indented with real tabs, because `make` rejects
  recipes indented with spaces.

## Developer Context and the entity router

- Opening a folder in Go Studio scans it locally:
  - `go.mod` modules and `package main` services;
  - docker compose services and datasources (Postgres, MySQL, Mongo,
    Redis, Kafka, RabbitMQ, NATS);
  - `.env` variables;
  - OpenAPI, proto and WSDL contracts;
  - Go routes (net/http 1.22, gin, echo, chi, gorilla);
  - `os.Getenv` / `env` tags, SQL tables and Kafka/AMQP/NATS topics.

  Every item keeps its `file:line`. Items derived from code are marked
  *inferred*.
- Saving in Go Studio rescans that file, and returning to the window
  rescans files changed elsewhere.
- Secret-looking `.env` values are masked, passwords in URLs and DSNs are
  redacted, and compose passwords are never read.
- **Ctrl+K** gains *Project* and *Symbols* groups: routes, tables, topics,
  services, env vars, contracts and gopls symbols of the active project.
  Enter runs the default action, and Tab lists every action.
- **Actions** (every item can also open its source in Go Studio):
  - route → Send in API Client, Go to handler, Add to Mock;
  - service → use as `baseUrl` (after confirmation);
  - datasource → Database or Broker Studio (the password is not copied);
  - contract → API Docs, gRPC or SOAP;
  - table → query;
  - topic → Broker Studio.
- A handoff to a panel that is still loading has a time limit and ends with
  a visible notice instead of being dropped silently.
