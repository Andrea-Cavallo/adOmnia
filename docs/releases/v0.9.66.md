# adOmnia v0.9.66 — Flexible tools, remote execution and extensions

This release brings together the modular workspace work and the remote-development,
Kubernetes, plugin and distribution changes completed alongside it.

## Shape Go Studio around your work

Run output, service logs, Terminal, Copilot Chat and milk can move left, right or
bottom, maximize in the workspace, or detach into a native window. Bring a tool
back or close its child window to return it to the project. Detaching removes
the tool from the IDE without an empty placeholder: code and remaining tools
automatically expand into its column or row. Bringing it back restores its position. The project continues
to own the processes and conversations. Drafts, filters and terminal selection are
shared in memory; terminal history transfers with a sequence checkpoint. Tool
positions are saved locally per session with an additive, backward-compatible key.

This is the first modular block: drag docking, arbitrary tab groups, named layout
presets and saved native window bounds remain future work. A native Copilot
window was opened and returned without closing the main app. The complete
multi-monitor, live AI-stream transfer and terminal process continuity smoke
check remains outstanding; see `docs/architecture/modular-workspace.md`.

## Connect code with runtime

Kafka topic detection now distinguishes producers and consumers and keeps both
roles when a topic is used in both directions. Saving a file refreshes removed
roles. Detection is local and static for literal names; ambiguous values remain
unclassified. The P2 work queue now tracks 188 open items, including 47 partial.

Run configurations can target WSL, SSH hosts or running containers. Paths are
mapped and remote process groups are stopped on input closure. SSH hosts and
containers also appear as terminal profiles. The editor and language server
remain local.

The Kubernetes pod Go tab forwards a configured Delve or pprof endpoint to a
free loopback port and hands it to Go Studio for debug attach, live profiles or
execution traces. Tools must already be exposed by the pod; this does not inject
Delve or enable pprof automatically.

## Extend adOmnia locally

Plugins support WASI modules through wazero, JSON input/output, captured stderr,
and memory/time limits with no filesystem, network or environment access.
Ed25519 signatures are verified at install; trusted keys identify trusted
plugins and modified signed files disable the plugin. Developer mode links a
source folder and hot-reloads changes with dedicated logs. Validated contribution
metadata declares commands, code actions, analyzers, templates, languages and
adapters; consuming these contributions in IDE menus remains tracked work.

## Distribution and documentation

Scoop, Homebrew, Snap and Flatpak templates plus a checksum renderer are included.
Optional Scoop/Homebrew automation requires configured bucket/tap repositories and
credentials. Snap Store and Flathub still require separate publication and review;
this release does not claim those channels are live. Release workflows now use
Wails v3.0.0-beta.26, matching the application, and package publishing conditions
use environment variables correctly.

Documentation and AI capability aliases now cover Insomnia and Bruno import/export.
The obsolete general todo file is removed; dedicated Go Studio and OpenShift
queues retain outstanding work.
