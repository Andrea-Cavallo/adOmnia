# v1.0.18 — lighter with several projects, faster CLI, new Hub

This release cuts the memory adOmnia uses when several projects are restored, makes
`adomnia mcp` start in ~40 ms even while the desktop app is open, fixes stress plans
exported from Flow Builder, and ships the redesigned Home Hub and Code Studio chrome.
No project data format changes and no migration is needed.

## Performance

- **Projects restored in the background no longer start Eclipse JDT LS.** Every Java
  project in the Code Studio list used to start its own JDT LS at launch, even when you
  were working on something else. With one Go project active and two Java projects in the
  list, the whole process tree goes from **2,084 MiB to 1,115 MiB (−47%)**. JDT LS now
  starts when a Java project becomes the active session, or when you open one of its files.
- **`adomnia mcp` starts in ~40 ms with the app open.** While the desktop app was running,
  every `adomnia mcp`, `run` or `stress` spawn waited a 250 ms database lock timeout and
  allocated a hidden console it never used: p50 was **278 ms**. It is now **42 ms with the
  app closed and 39 ms with it open** (25 cold starts, 0 failures), so agents that spawn the
  MCP server get their tool list without a noticeable wait.
- **Measured numbers in the README.** The *Performance* section reports window-visible time,
  MCP cold start, gopls workspace load, idle CPU, the whole process tree with a Go project
  open (≈1.1 GB across 10 processes), load-test throughput and clean shutdown, each with its
  method. The idle row now says it is the app process only, not the whole tree. Raw data:
  [stress-2026-10-24](../performance/stress-2026-10-24.md) and
  [runtime-2026-10-25](../performance/runtime-2026-10-25.md).
- **gopls memory budget decided with data.** Ten 10-minute typing runs: the default stays
  768 MiB; 512 MiB saves ~220 MiB but makes completion about four times slower, so it is a
  preset in the resource monitor with its cost stated, not the default.

## Stress and load testing

- **Plans exported from Flow Builder actually run.** `stress_run` and `adomnia stress`
  executed 0 requests on a `.stress.json` exported from the UI, and extractions and
  conditions were silently ignored. Plans now decode exactly what the UI writes, `extract`
  nodes apply their extractions, and a plan that cannot run is rejected with the reason.
- **Failures explain themselves.** Results group failed requests by their real message
  (`error ×20: dial tcp … connection refused`), APDEX counts failures as frustrated (an
  unreachable target reports 0.000, not 1.000), and a p95 gate with nothing measured fails
  instead of passing. The desktop Flow Builder uses the same rules.

## Home Hub

- **New Hub.** Electric adOmnia wordmark, dot-matrix clock, **Continue coding** (reopens the
  last file with its project) and the five most recent files.
- **Recent requests.** Up to five saved requests (method, name, URL, status, age), one row
  per method + URL: click one to reopen its captured response, or **History** for the full
  list.
- **Rotating copy.** The Hub title and the empty response panel show a different line on
  each visit, never the same one twice in a row.
- **Text follows your primary palette.** Hub headings, navigation and recent items take
  their tones from the accent colour, with a muted variant kept above WCAG AA contrast.

## Code Studio

- **Compact chrome.** Project and branch centred in the top bar, a searchable open-files
  switcher beside the tabs, collapsible tool windows, a status bar with file/symbol and
  document controls (LF ↔ CRLF with undo, language mode), a fixed Git marker column and a
  main menu that shows why a disabled item is unavailable.
- **Anthracite** appearance preset in Settings.

## Maintenance

- `fast-uri` 3.1.9 in the frontend lockfile; `aws-sdk-go-v2` 1.47.4 patch release.
