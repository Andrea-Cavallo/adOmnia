# adOmnia v0.9.56

Go Studio closes its foundations and becomes a performance tool. Profiles and execution traces open inside the IDE. The debugger shows where goroutines were born and which defers are still pending. Symbols move between packages with a build check before anything changes. Commits show real diffs, and local `replace` directives in go.mod can no longer reach other people's builds by accident.

## Performance Studio and Go trace

- **Profiles you can read.** *View → Performance Studio* (Alt+0) lists every `*.pprof` in the project, including the ones written by the CPU, memory, block and mutex options of a test configuration, and opens them in a tool window. Profiles are parsed locally with Google's pprof library: no `go tool pprof`, no external process, nothing leaves the machine.
- **Every pprof view you need:**
  - *Top functions*, flat or cumulative, with grouping by package, a filter that hides runtime frames, and search.
  - A flame graph with an icicle toggle.
  - Callers and callees of the selected function.
  - A sample-type selector, so `alloc_space` and `inuse_space` are read separately.
  - A diff against a second profile of the same kind.
  - One click on a function opens its source: project files in the editor, standard library read-only.
- **Execution trace viewer.** *View → Go Trace* reads `trace.out` with Go's own trace parser. It shows:
  - a timeline per goroutine (running, runnable, waiting, syscall) and per P;
  - GC and stop-the-world ranges;
  - waits grouped by network, synchronization, GC and sleep;
  - long-running goroutines;
  - runtime logs, tasks and regions.

  Every span opens its source.

## Debugger

- **Created at.** The goroutine detail shows the exact `go` statement that started the goroutine, read from the runtime, and the goroutine that ran it (*by goroutine #N*, one click to select it).
- **Real pending defers.** *Deferred calls* reads the goroutine's runtime defer chain. It lists only defers that actually ran, across every frame, in the order they will execute, each with its line and function. A `defer` inside a branch that was never taken does not appear. Debug builds disable open-coded defers, so the list is complete. On optimized binaries the panel falls back to the defer statements found in the source.

## Refactoring, coverage and Git

- **Move Symbol to Package.** *Code → Move Symbol to Package…* moves a func, var, const or type (with its methods) into another package of the module, new or existing:
  - References and imports are rewritten everywhere, tests included.
  - Moves that need unexported names, would create an import cycle or clash with an existing name are refused, with the reason.
  - The affected packages are compiled with the changes in an overlay before the preview opens, so a move that would break the build never touches your files.
- **Coverage against the base branch.** *Compare total with main* runs the same tests on the merge-base in a temporary Git worktree and shows both totals with the delta in points, plus the packages that are new in your branch. Your working tree is never touched.
- **Commit with real diffs.** The commit dialog is a large two-pane window. The files sit on the left; on the right is the diff of the selected file between HEAD and what will be committed, unsaved editor text included. The diff can be side by side or unified, with unchanged regions folded.
- **Local replaces in go.mod:**
  - Saving a go.mod with `replace example.com/lib => ../lib` comments out the other replace of the same module (`// adomnia-off: …`), because Go accepts only one. Removing the local replace brings the other one back.
  - Committing such a go.mod shows a warning.
  - Every push from adOmnia (Git Sync, Git Actions, account push, force push) asks for confirmation while the pushed commits contain a local replace.

## Editor and workspace

- **Images open.** PNG, JPG, GIF, WebP, BMP, ICO, AVIF and SVG files open in a read-only preview with zoom and fit-to-window. Local images in the Markdown preview now render too.
- **gopls activity you can see.** Starting, restarting or a crash of gopls shows an activity panel with progress, elapsed time and a *Force reload* button.
- **Shell picker next to the terminal tabs.** *+* and the shell menu (PowerShell, Command Prompt, Git Bash, WSL) sit right after the tabs, so they stay visible in a narrow panel.

## Reliability

- gopls was measured on a real monorepo (opentelemetry-go-contrib: 69 modules, 1585 packages). The workspace loaded in 3.7 s with a 255 MB heap once modules were cached. The numbers are in the Go Studio guide.
- The disaster-recovery tests run green on Windows, macOS and Linux.
- **Performance Studio accuracy fixes:**
  - Inlined calls are expanded into their own frames.
  - Cumulative values count each function once per sample.
  - The Top list keeps the leaders of every sample type.
  - *Diff* only compares the same kind of samples.
