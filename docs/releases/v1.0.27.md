# adOmnia v1.0.27

Reading the code of a Go dependency now works the way it should, and a Go file has its colors as soon as it opens.

## External Libraries

- **Dependencies in the Project tree.** Under the project, a new node lists the modules required by every `go.mod`, direct ones first, with the installed version. A version without a tag shows as commit and date.
- **The whole module, not only an entry file.** Expanding a module browses all of its folders and files, read-only. *View code* in `go.mod` used to open a single file and *Browse files* a flat list capped at 400 files. *View code* now also shows the module in the tree, and *Browse files* is gone.
- **The tree follows you.** Opening a dependency file from *View code*, Ctrl+click or Go to Definition expands the tree down to that file.
- **Does it have the latest changes?** The arrow on the node asks the configured Go proxy, also for modules without tags, and marks each module with `↑ version` or a check. It only contacts the network when you click it, and needs a trusted folder.
- **Local `replace` modules** appear with a `local` badge and open their real folder.

## Faster colors

- **Colors while gopls loads.** Functions, methods and types stay white until gopls answers, which on a large workspace took from a few seconds to over a minute. A local reading of the code now colors them as soon as the file opens, also in a folder that is not trusted. gopls replaces them with the exact ones.
- **gopls colors no longer get lost.** The request timed out after 15 seconds while gopls was loading, retried with growing pauses and gave up after six attempts, leaving the file without them. It now waits for gopls and they arrive as soon as it is ready.

The time gopls itself takes to load a workspace has not changed.

## Fixes

- **Downloading a module from `go.mod`** now waits for the download before opening the code, instead of reporting that the module is missing.

## Also new

- **Laser in the Hub.** A beam of light next to the clock, in the dark themes.

## Known limits

- External Libraries covers Go. Java, Python and Rust dependencies keep their existing views.
- The Go standard library is not listed in the tree. Its files still open with Go to Definition, without a position in the tree.
- A newly opened file shows the local colors first: some names can change color when gopls answers, and constants of other packages stay uncolored until then.
- Verified by automated checks and in the Windows app. macOS and Linux builds pass CI; native visual acceptance on them is still manual.
