# adOmnia 0.9.9 - Flow stress tests and faster variables

This release lets a developer put a whole API Flow under load and keep the
evidence, and makes `{{variables}}` quicker to work with everywhere.

## Flow stress test

- The **Stress** toolbar button opens a dock that runs the flow with up to 25
  concurrent virtual users. Configure ramp-up, a total number of iterations or a
  fixed duration, and a think time between iterations; Stop aborts at any time.
- Every virtual user runs the complete flow with its own variables, so tokens
  extracted by one user never leak into another.
- Progress, requests per second, errors, active users and a throughput sparkline
  update live. The per-step table shows count, p50, p90, p95, p99, max and error
  rate and flags the slowest step.
- Latency is the HTTP time measured by the Go executor. Step time also includes
  app overhead (bridge, scripts, retries) and is kept separately in the log.
- Normal runs and stress runs are mutually exclusive. Results stay in the session.

## Exports and baseline

- **CSV log:** one row per request with time, user, iteration, step, status,
  HTTP code, latency, step time, bytes and error.
- **JSON:** configuration, statistics and every request, re-importable.
- **HTML report:** a single offline file with summary cards, throughput chart and
  the per-step percentile table, in light and dark.
- **Compare with baseline:** load a previous JSON export to see the p95 change of
  each step (red above +10%, green below -10%) and the throughput change.

## Variables

- Right-click any `{{var}}` in the JSON body, URL, path params, query or headers:
  **Edit** its environment value, **Copy value** or **Copy** the `{{reference}}`.
  No need to select the token first. Selecting a literal in the body and
  right-clicking still extracts it to an environment variable.
- Inside a flow step, variables extracted by other steps are shown as defined
  instead of unresolved. The tooltip shows the last run value, or the step that
  produces it before the first run.

## Compatibility

- No storage or workspace format changes. Stress results are not persisted.
