# adOmnia v0.9.59

v0.9.58 made any module openable in its own window. This release makes that easy to reach and safe to use. You can open studios from the rail or straight from the IDE. Links from your code land in the window where the module lives. And the windows never lose or overwrite each other's edits.

## Open studios where you work

- **From the rail.** Right-click a module in a rail menu and choose *Open in a new window*. If it is already open, choose *Show window*. Shift+click does the same in one move. Detached modules carry a small window mark in the menu.
- **From Go Studio.** The new grid button in the toolbar lists API Workspace, Database Studio, Broker Studio, Mock Server, gRPC and Docker Lab. One click opens the studio beside the code, or brings it forward if it is already open. A dot on the button shows that something is detached. This also works from a Go project that is in its own window.

## Links from the code reach the right window

- **Every link from the code.** *Open in API Client*, *Send request* and *Add to Mock Server*, the Project Services handoffs (Database Studio, Broker Studio, Docker Lab), database, topic, gRPC and WebSocket connections, and *Open in Power Tools* all run in the window that owns the module and bring it forward. They no longer switch the main window behind you.
- **From a Go Studio project window.** Links go to the main window. *Open in Go* opens the code in the project window itself. Git, plugins, Search Everywhere panels, Log Inspector and Mock links bring the right window to the front.
- **From a module window.** *Open in Go* returns to the main window's Go Studio.
- **Imports land in the right place.** A collection imported from the project is written in the window where the API workspace is open. A detached workspace is never overwritten by a stale copy.

## Windows that never lose or overwrite edits

- **Saving before closing.** Closing a module window saves the edits still queued there first. This covers its X, *Bring back here* and quitting adOmnia. A frozen window still closes after 3 seconds.
- **Closing the main window.** The module windows close first, so adOmnia never keeps running with only a module window left.
- **One owner for the API workspace.** While it is open in its own window, the other windows never write their copy of collections, tabs, environments and hosts. They re-read it when it comes back.
- **Handoffs arrive.** A module window keeps its module selected even after startup restores the main window's last view. Handoffs sent to it are delivered instead of timing out.
- **The main window decides where adOmnia reopens.** Module and project windows no longer change it.
