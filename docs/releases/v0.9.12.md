# adOmnia 0.9.12 - a MongoDB explorer and a hidden game

This release turns MongoDB support in Database Studio from a JSON command runner
into a full explorer, fixes a MongoDB authentication failure, and hides a small
game in the hub. Everything stays local.

## MongoDB Explorer

- Mongo connections open an **Explorer** with a database and collection tree,
  estimated counts, create/drop collection, and a header with document count,
  storage, average document size and index size. The previous JSON runner is one
  click away through the **Explorer / JSON runner** switch.
- **Documents:** Filter, Project, Sort, Skip and Limit accept Extended JSON or
  mongosh syntax (`{ age: { $gte: 40 } }`, `ObjectId('…')`, `ISODate('…')`).
  Paging happens on the server with a total count. Documents render as an
  expandable list with typed BSON values, as JSON or as a table.
- Edit in place, clone, copy and delete individual documents. Edits keep their
  BSON types: an Int64 stays Int64 and a `1.0` Double stays a Double.
- Insert one or many documents, import JSON, NDJSON or CSV (dotted headers
  become embedded documents), and export every document matching the filter.
- **Explain** shows whether a query scans the collection or uses an index, with
  documents and keys examined and the winning plan tree.
- **To code** exports a query or pipeline as mongosh, Node.js, Python, Go or Java.
- **Aggregations:** a stage builder with operator picker, enable/disable,
  reordering and a live preview of each stage's output. `$out` and `$merge` never
  run in previews and ask for confirmation before a full run.
- **Schema:** samples up to 10,000 documents (respecting the current filter) and
  shows every field path with type distribution, presence and sample values.
- **Indexes:** keys, type, size, usage and unique/sparse/partial/TTL/hidden
  properties; create compound, unique, sparse, TTL and partial indexes; drop.
- **Validation:** edit `$jsonSchema` rules with validation level and action.
- Connections accept URI options such as `authSource=admin&tls=true` and SRV
  (`mongodb+srv`) hosts.

## Fixes

- MongoDB connections failed with `unable to authenticate using mechanism
  "SCRAM-SHA-1": (MechanismUnavailable)` when the user did not exist in the
  default `authSource`. adOmnia now retries with SCRAM-SHA-256 and, for
  field-based connections, with `authSource` set to the selected database. Real
  authentication failures explain how `authSource` works.
- The hub logo's three-turn gesture lost progress each time the pointer passed
  its starting point; exactly three turns now registers. The logo keeps its
  fidget momentum and then eases back upright.

## a0: Bug Hunt

Spin the hub logo three full turns, or hold it for 30 seconds. The first level,
Localhost, is a short platformer about a Friday deploy: stomp bugs, collect
bits, find the secret branch, grab the Hotfix and turn the pipeline green.
It loads only when opened, runs offline with synthesized audio, pauses on Esc
or when the window loses focus, keeps a local best time, offers a gentle-effects
mode and follows the app language. Levels 2 and 3 are planned in
`docs/BUG-HUNT.md`.

## Verification

- Go database tests, 509 frontend tests and TypeScript checks pass.
- The MongoDB explorer was exercised end to end against MongoDB 7 with
  SCRAM-SHA-1 disabled.
- The game was played in the Wails 3 desktop runtime (WebView2): both secret
  gestures, pause, exit and repeated reopening, at the display refresh rate.
