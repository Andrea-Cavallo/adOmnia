# adOmnia 1.0.6 — Strix nel Security Center, reachability che spiega, README nell'anteprima

19 ottobre 2026.

## Novità

- **Pentest con Strix (Security Center → Pentest · Strix).** Agenti AI che provano a sfruttare le falle del progetto in un sandbox Docker, su una copia privata (i tuoi file non cambiano, `.env` e chiavi restano fuori). Si sceglie il progetto tra gli ultimi aperti, la profondità, il budget e l'**agente**: Settings → AI oppure una qualunque chiave trovata negli Environments. Ogni scansione parte solo dopo una conferma che dice che il codice va al provider scelto. Risultati per finding e report completo esportabile in Markdown.
- **Reachability con il motivo.** Ogni "Not analyzed" dice perché: Deep analysis spenta, strumento fallito, advisory fuori dal database Go, progetto Maven non compilato.
- **Security Center ridisegnato** nello stile minimale a puntini del resto dell'app.
- **Module Dependencies per `pom.xml` e Gradle**, con vulnerabilità, aggiornamenti e modifica della versione nell'editor; **Resources** (RAM, CPU, processi, export Markdown) sotto la barra destra di Code Studio.
- **HTML nei Markdown.** I README con `<p align="center">`, `<img width>`, `<br>` o `<details>` si vedono formattati anche nell'anteprima dell'IDE.
- Export Markdown del report dipendenze e del pannello Problems; `secscan -deep` per la CI.

## Correzioni

- **Reachability sempre "Not analyzed".** Un `govulncheck` compilato con un Go più vecchio falliva e l'errore veniva ignorato. Ora è segnalato e c'è *Rebuild govulncheck*; quello ricompilato vince su una copia vecchia nel PATH. Lo stesso vale per golangci-lint.
- Il menu Export del Security Center si chiudeva appena ci si avvicinava.

## Da sapere

Strix ha bisogno di Docker acceso e di una chiave API del provider AI (un login Claude Code o Copilot via abbonamento non basta). Restano da provare nell'app le voci SEC-3.M1–M6 di [MANUAL-CHECK.md](https://github.com/Andrea-Cavallo/adOmnia/blob/v1.0.6/mds/MANUAL-CHECK.md).
