# adOmnia v1.0.25

Own the OSGi workspace you already have: open a large Java 6 / Eclipse Kepler / Tycho project without migrating it, see why a bundle does not start, run it in the real Equinox, follow its flows and let an agent work on it with the same engine.

## OSGi Control Center

- **One place for the whole workspace.** The Control Center lists every bundle with its state, Activator, start level and issues; search, filters and paging stay fast on workspaces with hundreds of plug-ins.
- **Why a bundle does not start.** Diagnostics name the real cause (version conflict, missing requirement, Java level, missing Activator, platform filter) with the exact MANIFEST line. A bundle built for another OS is *info*, not an error.
- **Focused graph and impact.** See who requires what, who provides a package, and what moving a bundle or a class would break, with one click to the source.
- **Target platform.** A Tycho `pom.xml` (including a parent pom with `<relativePath>`) or an existing target file gives the index; loose target JARs can be imported, and two targets can be compared.
- **Manifest editing.** Headers are rewritten preserving order and line endings, re-parsed before saving, with the usual version-range fix offered for an unresolved import.

## Run it in Equinox

- **Runtime tab.** Start the compiled bundles with the project JVM, on the real Equinox console (loopback, ephemeral port): ACTIVE bundles with the first activation time, framework start level, the service registry with providers and consumers, and the `diag` explanation.
- **No guessing.** ACTIVE states and services come from the running framework, never from the static model.

## Flow Intelligence

- **The execution path of legacy code.** `Java -> Flow Explorer...` searches flows, subflows and methods, draws the call path grouped by bundle (down, up or both, depth 1-8), and shows the impact of a change with the evidence behind every link.
- **Honest confidence.** Every relation says how it is known: `declared` (configuration, XML, annotation), `derived` (resolved inside the workspace), `inferred` (name/import heuristic) or `observed` (runtime). Method-level runtime paths are not faked: observing them needs bytecode instrumentation.
- **Runtime evidence.** *Runtime* in the Flow Explorer marks ACTIVE bundles, lists registered services with provider and consumers and counts the edges the runtime proves.
- **Flows are pluggable.** A declared `.adomnia/flows.json`, generic XML, Java `@Flow`/`@Subflow` annotations and OSGi metadata are read together, so a proprietary format can be added as one more adapter.
- **Fast on large workspaces.** The index is persisted in adOmnia's data folder (never in the project) and rebuilt only when the sources change; a 300-bundle synthetic workspace guards discovery time and bounds the trace.

## Work with an agent

- **`adomnia mcp <project> [--write]`.** An agent can read the workspace, bundles, wiring, diagnostics, target, services and flows, and can write manifests, requirements, targets and files only when `--write` is given. Writes are atomic, confined to the project and refuse to overwrite a concurrent edit (SHA-256 check).
- **Same engine as the app.** No second analysis, no second graph: the IDE and the MCP server ask the same Go code.
- **The running framework too.** An agent can start Equinox, read the snapshot and stop it; the JVM belongs to the server and dies with it.

## Find in Files on ripgrep

- **The fast engine.** Search in Files runs ripgrep, bundled with the Windows, Linux and macOS packages (14.1.1, SHA-256 verified, with its license files); `ADOMNIA_RG` overrides the path. When the binary is missing, the built-in Go engine takes over: search keeps working.
- **Results while you type.** The search starts 200 ms after the last keystroke and a new query cancels the previous one; results stream into the panel instead of waiting for the scan to finish, and only the visible rows are rendered, so thousands of hits scroll smoothly.
- **Honest errors.** "No results" is not an error; an invalid pattern, an unreadable root or a bad glob is reported with ripgrep's message.

## Also in this release

- Java on a PDE workspace no longer starts JDT LS, which cannot read a target platform and refuses Java below 8. The notice says it plainly and points to **Java -> Build OSGi Bundles**, which compiles with the target's ECJ on the project JVM (Java 6 included).
- Rust language servers are grouped per Cargo workspace and capped, so a big workspace no longer launches dozens of `rust-analyzer` processes.
- Generated bindings are part of the repository, so a clean checkout builds without a manual Wails regeneration.

## Known limits

- No export of bundles to JAR from `build.properties`, no `features`/`p2` publishing.
- Bundles that exist only as compiled JARs contribute OSGi metadata, not a method graph.
- Method-level live tracing is not implemented.
- Starting Equinox has not been verified against a real Eclipse installation; it uses the target's Equinox 3.9-era bundles.
