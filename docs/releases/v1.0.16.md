# v1.0.16 — clean version for the Claude Code, key and AI hub fixes

v1.0.15 was published twice on 2026-10-22: the first build did not contain three
fixes that were added afterwards, and the tag was then recreated with them. Two
different builds under one version number is confusing, so this release gives the
corrected code its own number. There is no new code beyond v1.0.15 as it stands
now; if you installed v1.0.15 earlier today, update to v1.0.16.

## What you get compared with the first v1.0.15 build

- **Claude Code opens again on Windows.** The launcher found npm's `claude.cmd`,
  which Node cannot spawn (`spawn EINVAL`), so opening a session failed with
  *milk error -32603: Internal error*. It now uses the `claude.exe` bundled with
  the npm package, then a `claude.exe` on PATH, and an executable you set
  yourself is no longer overridden.
- **Agents without a key are flagged and refused.** milk's primary selector marks
  an agent whose key variable adOmnia does not see (*key missing*) and refuses it
  as primary, and the milk settings warn when the primary or escalation agent
  cannot authenticate. Choosing a provider again repairs a stale key reference,
  such as Gemini reading `GEMINI_API_KEY` while the key is stored in
  `GOOGLE_GENERATIVE_AI_API_KEY`.
- **Switch Copilot, milk and Claude Code on or off from their tab.** A power
  button on each tab of the AI Assistant turns the provider off (stopping its
  process) or on.

Everything else in v1.0.15 (`node --test` in the Test tree, Nest and Next
suggestions, Spring datasources in Database Studio, Java Code Vision, milk
turn timeout and routing chip, OpenCode out of the hub) is unchanged; see
[v1.0.15](v1.0.15.md). No project data format changes and no migration is needed.

## Verification

Full Go suite, `go vet ./...`, `npx tsc --noEmit`, the whole Vitest suite (2230
tests) and the Claude Code session opening against the real adapter pass. The
desktop checks of the new behaviour are in `mds/MANUAL-CHECK.md` and have not been
run in the app yet.
