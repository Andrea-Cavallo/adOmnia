# adOmnia 0.9.3 — Request-level Log Inspector analysis

Log Inspector now turns structured microservice output into an end-to-end view
of the requests a developer is debugging. The analysis stays local and runs
deterministically over the parsed events.

## Requests instead of isolated lines

Events are grouped by `correlation_id`, with `request_id` as fallback. The new
request table shows operation, endpoint, method, final HTTP status, duration,
service and downstream clients. Clicking a row filters the event list to that
request, so the summary remains directly connected to the raw evidence.

Each chain is classified as success, client error, server error, timeout, retry
or unknown. The analyzer understands the JSON shapes commonly emitted by Go
`slog`, zap and zerolog and by JSON logback encoders, including both nested and
dotted keys:

- `attributes.layer`, `attributes.operation`, `attributes.client`,
  `attributes.status`, `attributes.latency_ms`, `attributes.error`;
- `http.route`, `http.method`, `http.status_code`, `event.outcome`,
  `duration_ms`;
- `service.name`, `service.version`, `environment`, `k8s.pod.name`,
  `k8s.namespace.name`;
- `source.file`, `source.function`, `source.line`.

The event detail view promotes these fields into readable Operation and Runtime
sections while preserving the complete JSON tree.

## Diagnostics calibrated for enterprise service logs

`context deadline exceeded` is identified as a timeout even when it appears in
an attribute rather than the message. When the named downstream reports roughly
10,000 ms latency, the action explicitly points to that client's health, latency
and HTTP deadline. HTTP 4xx responses and validation signals such as
`dean obbligatorio` become client errors; 5xx responses and error outcomes become
server errors. Completed or successful chains are marked as success.

This behavior was manually checked with five distinct requests across
`maul-transaction-ms` and `sidious-access-ms`: GetHistory, a failed validation,
GetBalance, a WalletEDIG timeout and CreateAlias.

## Sensitive payload awareness

The analyzer reports paths that appear to contain clear-text fiscal codes,
IBANs, DEAN identifiers, PANs, phone numbers or secrets. It never repeats their
values in the analysis. The same fields are now part of the built-in masking
set, including nested request and response bodies.

## Reliable imports and large logs

Starting a new file or clipboard import invalidates every older acquisition and
parse. Clear discards late callbacks completely; Cancel stops parsing and keeps
the partial result. Background work is cancelled when the panel closes.

Progressive list snapshots are limited to ten updates per second, and request
analysis begins only after parsing completes. Correlation duration uses an
iterative scan, so very large chains cannot overflow the JavaScript argument
stack. Structured exports now include the original JSON payload, line count and
mixed-log prefix.
