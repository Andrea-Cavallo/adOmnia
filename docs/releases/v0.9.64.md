# adOmnia v0.9.64

The AI in gO Studio now knows more than the open file. Each editor AI action writes a prompt from the real state of your project: the code, its errors, who calls it, what you changed, which tests fail, what is covered and how the project is built. milk can also use the API keys you already keep in your environment.

## AI actions in the editor

Right-click in a Go file:

- *AI: Explain Code*
- *AI: Explain Error*
- *AI: Generate Tests*
- *AI: Improve Error Handling*
- *AI: Find Race Risks*
- *AI: Generate Docs*

The command palette (F1) also has:

- *Generate Benchmark*, *Generate Fuzz Target* and *Generate Mock*
- *Find Goroutine Leaks*, *Find Allocation Hotspots* and *Find Missing Context Propagation*
- *Explain Dependency* and *Explain Architecture*
- *Generate API Call*, *Generate SQL Query*, *Generate Migration* and *Generate Kafka Message*

Every action attaches only the context that exists:

- **Code:** the selection, or else the function or type at the cursor.
- **Problems:** the compiler and linter problems of the file.
- **References:** gopls references to the symbol at the cursor.
- **Changes:** the uncommitted Git diff of the file.
- **Tests:** the failing tests of the last run, and the file's coverage with the functions not fully covered.
- **Project analysis:** the Architecture Explorer's analysis, only for the actions that need it. Explain Architecture gets packages and imports, Explain Dependency gets modules and external packages, Generate API Call gets endpoints with their request and response types, Generate SQL Query and Generate Migration get queries, tables and types, and Generate Kafka Message gets producers, consumers and topics.

The prompt opens in the milk or Copilot chat, whichever is open or ready, and is sent only when you press Enter. Secrets are redacted first. Files excluded by `.adomnia/aiignore`, or by a project AI policy that is `off` or `local-only`, are refused.

## milk agents from your environment

*milk settings → Models from your environment* lists DeepSeek, OpenAI, Gemini, OpenRouter, Groq and Mistral. For each one it shows whether its key variable is set; it shows the variable's name only, never its value. *Primary* or *Escalation* adds the agent to `~/.milk/config.json` with a `token_cmd` that reads the variable each time milk starts, so the key is never written to disk. The rest of milk's config is kept, a `.bak` copy is saved first, and milk restarts by itself. Set a variable after starting adOmnia? Restart adOmnia so it can see it.
