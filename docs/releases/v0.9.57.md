# adOmnia v0.9.57

Go Studio becomes the adOmnia IDE Platform, with Go as its first language. You still see the same Go IDE, but underneath, project detection, language servers, Run/Test and the debugger now go through a language-neutral core, and the UI learns its languages from the backend. This release also adds optional SonarQube analysis, one-click profiles and traces, and redesigned performance charts.

## SonarQube in Go Studio

- **Optional and off by default.** *View → SonarQube* (or **Sonar** in the status bar) configures a server: URL, project key, sources and exclusions.
- **Scan, then import the results.** Go Studio runs `sonar-scanner` on the trusted project and waits for the server to finish processing, so the issues it imports are the new ones.
- **Readable results.** Issues are listed by severity with file:line navigation, a security-only filter and per-severity counts.
- **Act on them.** *Copy problems* copies every shown issue, and *Resolve with AI* uses the preview-before-apply fix flow.
- **Baseline.** `.adomnia/sonar-baseline.json` hides existing debt, so only new problems show.
- **Safe by design.** Works with SonarQube 9.9 LTA, 10.x and SonarCloud. The scan respects Offline mode and the corporate proxy/CA. The token stays in memory for the session only.

## Performance

- **Create a profile or a trace in one click.** *Create .pprof* (CPU, Memory, Block, Mutex) and *Create trace.out* run the tests of the package you pick, save a timestamped file and open it.
- **Redesigned charts:**
  - one colour-blind-safe palette by code origin;
  - a pixel-exact flame graph with zoom and tooltips;
  - a caller → function → callee view;
  - a trace timeline with a time axis and a GC/stop-the-world lane.
- **Reports for AI.** Performance Studio and Go Trace export the current view as Markdown for an AI assistant: copy it, save it, or send it to Copilot. Paths in the report are project-relative only.

## IDE Platform

- **One core for every language.** Language registry, project units, SDK plumbing, language-server lifecycle, Run/Test orchestration and DAP debugging live in a language-neutral core, and the Go tools sit in the Go adapter. Service names, settings, workspaces and saved run configurations stay compatible.
- **Languages in the UI.** Each language contributes its icon, menu, commands and editor languages. Editor features such as completion, hover, navigation, formatting, semantic highlighting, inlay hints and code vision are no longer tied to Go. The status bar shows the active file's language icon.
- **Language icons.** The project tree shows brand icons for Java, Kotlin, PHP, Ruby, .NET, C, C++, Swift, Dart, Scala, Elixir, Haskell, Lua and Zig, and for Maven and Gradle build files.
- **Project model without Go fields.** Go modules, `go.work` and loose folders are derived from the project's language units. Sessions saved by older versions are re-read on restore.

## Fixes and updates

- **Run/Test edge cases:**
  - fast runs, and output that ends without a final newline, are handled;
  - concurrent Docker callbacks keep separate Rerun requests;
  - test package paths stay confined to the project.
- **Workspace symbols.** Results from a healthy language server are kept when another server times out.
- **Context menus.** Menus near the left edge of the window stay on screen.
- **Run icon.** The Run tool window uses the Play icon, so it no longer looks like the Terminal one.
- **Dependencies.** Wails v3.0.0-beta.26, xterm.js 6, Monaco 0.57, Vite and Vitest patches, fsnotify 1.10.1, sarama 1.61.1, modernc.org/sqlite 1.60.1.
