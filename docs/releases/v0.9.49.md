# v0.9.49 — Live Development Session, a real terminal toolbox and no title bar

Code and requests now share one running service, the Go Studio terminal gets
the tools of an IDE terminal, the window loses its separate title bar, and
Go Studio stays responsive on large projects and on battery.

## Live Development Session

- A Go service started from Go Studio (Run or Debug) is shared by every tool.
  A debug bar shows the service, its port, the paused location and Continue /
  Step / Stop (F9, F8, F7, Shift+F8, Ctrl+F2).
- **Debug Request** starts or reuses the service under Delve, waits for its
  port or health path, sends the request and shows *Paused at breakpoint* with
  Open in Go Studio. The response waits for the debugger.
- `{{service:name}}` linked requests with Local / Docker / remote targets, the
  handler that serves a request (with contract drift against the service's
  OpenAPI), handler CodeLens in Go Studio and a Request tab in the debugger.
- Logs, Debug, Timeline, DB and Kafka views of what a request caused, tied by
  `X-AdOmnia-Request-ID` or by time; SQL from service logs or an opt-in
  loopback capture proxy (Postgres, MySQL); a Kafka watch without consumer
  group; *Mock this response*.
- Go Studio and the API Workspace stay mounted across tool switches; Split
  Debug View; Ctrl+Tab context switcher; Alt+Shift+1…5 tool keys.

Full guide: [docs/LIVE-SESSION.md](../LIVE-SESSION.md).

## Go Studio terminal

- **Rename** a terminal with a double-click on its tab; the name survives a
  project switch.
- **Split** shows two terminals side by side.
- **Ctrl+click** on `file.go:12:5` or on a stack-trace frame opens the file in
  the project, GOROOT or the module cache.
- **Ctrl+F** finds in the scrollback; **Copy output** copies plain text
  without colors or control codes; **Clear** empties the scrollback.
- **History** keeps the last 50 commands of each project locally. Commands
  that mention tokens, passwords or keys are never stored, and a picked
  command is typed without pressing Enter.
- Typing `go test …` offers **Run in Test Explorer** with the same packages
  and `-run`, `-bench`, `-race`, `-cover`, `-tags`.

## No separate title bar

- With the integrated window chrome the "adOmnia paratus." strip is gone:
  the panel header is the window bar. Drag from empty space, double-click to
  maximize; minimize / maximize / close sit at its right. The Welcome hub
  shows floating window controls.
- **App titlebar is the default** on Windows and macOS from the very first
  launch. Linux keeps the system frame (WebKitGTK/Wayland). An explicit
  *System titlebar* choice is kept.

## Performance and low-resource mode

- **Low-Resource Mode** (View menu) pauses semantic highlighting, inlay and
  type hints, sticky scroll, the minimap and lint on save without changing
  your preferences; a *Low-resource* badge in the status bar turns it off.
  **Low-Resource Mode on Battery** applies it only while a laptop is
  unplugged (Battery Status API in WebView2; elsewhere it stays normal).
- gopls diagnostics are coalesced to one update per file every 150 ms, and at
  most 1000 diagnostics per file reach the UI, errors first.
- The Run console draws the last 5000 lines (search and Copy still use the
  whole 4 MB buffer). Project folders with more than 500 entries load in
  pages, and off-screen tree rows are not laid out.

## Debugger, tests and benchmarks

- Runtime Inspector for the paused frame: slice `len`/`cap`, map size,
  channel queue and capacity, interface dynamic type, context fields and the
  `Unwrap()` error chain (resolved only on request, since it runs code in the
  stopped process). The panic inspector opens the frame that panicked.
- *Inspect source* on a debug frame reports STATIC hints: opposite lock
  ordering, `wg.Add` inside a new goroutine, un-called context cancel funcs
  and timers/tickers without `Stop()`. Deferred calls of the frame are listed
  as source candidates.
- Race reports: the last 20 sources are kept per project and each race offers
  *Copy regression test starter*.
- Test Explorer: search, failed and slow filters, rerun package, debug a
  single test or subtest.
- Benchmark Studio: run one benchmark or the whole package with `-benchmem`,
  iterations, duration, ns/op, B/op, allocs/op and custom metrics; local
  history of the last 120 measures, comparison with the previous run and CSV
  export.
