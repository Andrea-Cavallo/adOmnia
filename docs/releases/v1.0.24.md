# adOmnia v1.0.24

## Windows installer

- New `adomnia-1.0.24-windows-amd64-setup.exe`: per-user install in `%LOCALAPPDATA%\Programs\adOmnia`, no administrator rights and no UAC prompt.
- Start menu shortcut, optional desktop shortcut, entry in Installed apps with version and uninstaller.
- Upgrades an installed copy in place and asks to close adOmnia if it is running. Workspaces, collections and settings are kept.
- Warns when the WebView2 Runtime is missing and links Microsoft's installer.
- The uninstaller deletes user data only when "Also delete my data" is ticked. Silent mode: `/S`.
- The portable `adomnia-1.0.24-windows-amd64.exe` is still published.

## Automatic updates

- The updater knows how adOmnia was installed: Windows installer, portable copy, macOS app, or a read-only / package-managed location.
- Installed copies update in place and keep the version in Installed apps current.
- Copies adOmnia cannot write are never downloaded for: Settings and the update notice show why, with a link to the release.
- Verified updates download in the background by default; installing still waits for **Save & restart** or **Install on exit**.

## Release pipeline

- The tag is validated before any build.
- Windows binaries are Authenticode-signed when a code-signing certificate is configured.
- The release is uploaded as a draft and published only after every download and the signed update manifest are present.

## Verification

- Go update package tests, `go vet` for Linux, Windows and macOS, golangci-lint: passed.
- Frontend TypeScript, oxlint, update and settings tests, startup bundle check: passed.
- The NSIS installer compiles with warnings as errors.

The installer has not yet been run on a physical Windows machine; GitHub Actions builds it on the Windows runner with every build.
