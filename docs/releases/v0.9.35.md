# v0.9.35 — Go Studio foundation

## A local-first IDE boundary

- Go Studio now has its own `internal/goide` domain rather than placing IDE
  behavior in the Wails binding layer.
- Workspace, documents, toolchain, processes, LSP, terminal, debug, tests and
  persistence have separate ownership and lifecycle boundaries.
- Commands and events use explicit session, document, run, terminal, LSP and
  debug identifiers. Event envelopes are versioned, sequenced and timestamped.
- Process output, pending requests, terminal scrollback and document sizes have
  explicit limits from the start.

## Safe project sessions

- A folder can be opened as a Go Studio session without running source code,
  scripts, tests, hooks or project-defined commands.
- Project-open state is separate from permission to use local development
  tools. Granting or revoking that permission does not start a process.
- Roots are resolved through symlinks and document paths are confined to the
  real project directory.
- Session metadata is stored locally in a versioned bbolt bucket. File
  contents, environment values and credentials are not persisted there.

## Integrated shell

- The existing adOmnia rail gains a dedicated compact `gO` entry while Git
  Sync remains in Workspace.
- Go Studio is lazy-loaded through the normal router and is discoverable in the
  command palette and assistant capability catalog.
- Its dedicated Zustand store keeps IDE sessions and persistent layout state
  separate from HTTP tabs and other product areas.
- The initial dense, dark workspace reserves the project tree, editor,
  structure panel, lower tool window, toolbar and status bar. Only real actions
  are shown: open a project, select a session, explicitly authorize tools and
  close a session.

## Architecture decisions

- The ADR defines stdio JSON-RPC for gopls, document versioning and
  cancellation, ConPTY-first terminal support on Windows, Unix adapters behind
  build tags and Delve DAP over a lifecycle-controlled loopback connection.
- Separate windows remain a documented future capability until tested. Go
  Studio does not add a local network service in this release.
- The approved IDE and `aO → gO` visual references are recorded in
  `todo-ide.md`. Future functionality must pass its phase gate before becoming
  visible.

## Intentionally not included yet

- No editor, file tree, build, run, terminal, gopls, test runner or debugger is
  presented as complete. These features remain gated in the implementation
  checklist.
- Opening a session never downloads or installs a toolchain or dependency.

## Verification

- 565 frontend tests pass across 122 test files, together with TypeScript and
  the production Vite build.
- `go test ./...`, `go build ./...`, `go vet ./...` and
  `go test -race ./internal/goide` pass.
- The Go Studio package cross-builds for Linux and macOS.
- Wails beta.25 bindings were regenerated. The Windows desktop runtime was
  built and launched with an isolated local profile, and the rail plus command
  palette paths were exercised in the local preview.
