# v0.9.33 — a0 can act on the workspace

## Agent actions

- Settings → AI Engine now includes an explicit **Agent actions** permission.
  It controls whether a0 may apply supported mutations requested in chat.
- With permission disabled, a0 remains advisory and explains that Agent actions
  must be enabled. Enabling it does not expose credentials or grant arbitrary
  filesystem access.
- With permission enabled, a0 can return validated workspace actions instead of
  telling the user to recreate its suggestion manually.

## Root API requests

- The first supported workspace mutation is `create-request`.
- a0 can specify a request name, HTTP method, URL, safe headers and an optional
  body. adOmnia validates and bounds each field before creating anything.
- Created requests use the existing Quick Requests storage path, so they appear
  at workspace root outside user collections and remain compatible with current
  workspace persistence.
- The new request opens immediately for review; a0 reports success only after
  the local mutation has completed.

## Greeting API command

- Explicit English and Italian commands to create a greeting API outside the
  collections have a fast deterministic handler.
- The command creates `Greeting API` as
  `GET http://127.0.0.1:3000/hello` with an `Accept: application/json` header.
- Negative requests such as “non creare” are ignored by the mutation handler.
- This deterministic path avoids falling back to unhelpful setup instructions
  when a provider does not follow the structured JSON schema.
