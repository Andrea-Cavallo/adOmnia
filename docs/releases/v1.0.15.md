# v1.0.15 — `node --test`, Nest/Next suggestions, Spring datasources and milk fixes

This release closes a gap in the JavaScript/TypeScript tooling, connects Spring
projects to Database Studio and fixes how milk picks its agent. No project data
format changes and no migration is required.

## Code Studio

- **`node --test` in the Test tree.** A `test` script that runs `node --test` is
  now a test runner of its own, used when the project declares neither Vitest nor
  Jest. The tree shows every file, suite and test with pass/fail/skip, durations
  and a clickable failure location; a file that cannot start (for example a
  missing import) is reported as failed with its message. It needs no
  `node_modules`. Node's own reporters do not say which file a passing test
  belongs to, so adOmnia ships a small reporter that is written once to the user
  cache folder (never into the project) and passed to Node as a `file://` URL.
- **Nest and Next suggestions.** The Run bar recognises Nest (`nest start`,
  `@nestjs/cli`, `@nestjs/core`) and picks `start:dev` as its development script;
  before, only `start` was found and Nest ran without watch. Next and Nest also
  offer the production start (`start` / `start:prod`), never repeating a command
  that is already the dev script.
- **Spring datasources in Database Studio.** Project Services reads
  `spring.datasource.*` from `application.properties` / `.yml` and their
  profiles (URL or separate host/port/database, username, driver) with the file
  and line it came from. The password is never copied: only its presence is
  known.
- **Java Code Vision and override markers.** Usage counts and the latest git
  author above declarations, with implementation markers from the language
  server.

## AI assistants

- **milk agent changes take effect.** Choosing the primary or escalation agent
  restarts `milk serve --acp`, so the choice is no longer silently ignored.
- **Turn timeout.** milk settings gain a *Turn timeout* (default 10 minutes, max
  120): a longer turn is cancelled and reported. Stop still interrupts at once.
- **The routing chip names the real agent** that served the turn.
- **Xiaomi MiMo default model** corrected to `mimo-v2.6-flash`.
- **Claude Code opens again on Windows.** On Windows the launcher found npm's
  `claude.cmd`, which Node cannot spawn (`spawn EINVAL`), so opening a session
  failed with *milk error -32603: Internal error*. It now uses the `claude.exe`
  bundled with the npm package, then a `claude.exe` on PATH, and an executable
  you set yourself is no longer overridden.
- **Agents without a key are flagged and refused.** milk's primary selector
  marks an agent whose key variable adOmnia does not see (*key missing*) and
  refuses it as primary, and the milk settings warn when the primary or
  escalation agent cannot authenticate. Choosing a provider again repairs a stale
  key reference, such as Gemini reading `GEMINI_API_KEY` while the key is stored
  in `GOOGLE_GENERATIVE_AI_API_KEY`.
- **Switch Copilot, milk and Claude Code on or off from their tab.** A power
  button on each tab of the AI Assistant turns the provider off (stopping its
  process) or on.
- **OpenCode is out of the AI Assistant hub for now.** Its tab, chat pane,
  settings dialog, Tools command and detached window are gone and its ACP service
  is no longer registered.
